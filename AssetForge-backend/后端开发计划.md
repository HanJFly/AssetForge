# AssetForge 后端开发计划

> 按数据依赖顺序开发，从基础到复杂，每步建立在前一步基础上。

## 开发路线

```
公共基础设施 → 系统管理(用户/角色) → 部门管理 → 资产分类 → 资产登记 → 资产台账 → 审批流程 → 资产流转(申领/转移/归还/报废) → 月度折旧与快照 → 盘点模块 → 报表模块
```

---

## 阶段一：公共基础设施

**目标：搭建统一的代码规范和通用组件**

### 需要创建的类

| 类名 | 位置 | 作用 |
|------|------|------|
| `Result<T>` | `common/result/` | 统一返回结果封装 |
| `GlobalExceptionHandler` | `common/exception/` | 全局异常处理 |
| `CorsConfig` | `config/` | 跨域配置 |

### 统一返回格式

所有接口返回格式：

```json
{
  "code": 200,
  "msg": "success",
  "data": { ... }
}
```

常见状态码：
- `200` — 成功
- `400` — 参数错误
- `401` — 未登录
- `403` — 无权限
- `500` — 服务器内部错误

### 跨域配置

允许前端（通常是 5173 端口）访问后端 API。

### 条码生成规则

格式：`AST-YYYYMMDD-NNNNNN`

示例：`AST-20260614-000001`

- 前缀：`AST-`
- 日期：年月日（8 位）
- 流水号：6 位数字，每日从 000001 重新开始

### 关键接口

- `POST /api/asset/register` — 资产登记（提交后状态为待审批）
- `POST /api/asset/approve/{id}` — 审批通过（状态变为库存）
- `POST /api/asset/reject/{id}` — 审批驳回
- `GET /api/asset` — 查询资产列表（支持多条件筛选）
- `GET /api/asset/{id}` — 查询单个资产
- `PUT /api/asset/{id}` — 修改资产信息
- `DELETE /api/asset/{id}` — 删除资产（软删除）

### 业务流程

```
登记资产 → 生成条码 + 继承分类年限 → 状态：待审批
  → 管理员审批通过 → 状态：库存 → 创建台账记录
  → 管理员审批驳回 → 状态：已驳回
```

### 资产状态流转

```
登记审批通过 → STOCK(库存) → 申领出库 → ASSIGNED(领用) → 归还 → STOCK(库存) → 转移 → ASSIGNED(领用) → 报废 → SCRAPPED(报废)
```

### 实体字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键 |
| ledgerNo | String | 台账编号（唯一） |
| assetId | Long | 资产 ID |
| departmentId | Long | 所属部门 ID |
| departmentName | String | 所属部门名称（冗余快照） |
| entryDate | LocalDate | 入账日期 |
| originalValue | BigDecimal | 原值 |
| residualRate | BigDecimal | 残值率（默认 0.05） |
| standardLifeMonths | Integer | 标准使用年限 |
| monthlyDepreciation | BigDecimal | 月折旧额 |
| accumulatedDepreciation | BigDecimal | 累计折旧（初始 0） |
| netValue | BigDecimal | 现值（原值 - 累计折旧） |
| monthsUsed | Integer | 已使用月数（初始 0） |
| isDeleted | Integer | 软删除标记 |
| createdAt | LocalDateTime | 创建时间 |
| updatedAt | LocalDateTime | 更新时间 |

### 折旧计算公式

```
月折旧额 = 原值 × (1 - 残值率) ÷ 标准使用年限
资产现值 = 原值 - 累计折旧
```

示例：原值 12000 元，标准使用年限 36 个月，残值率 5%：
- 月折旧额 = 12000 × (1 - 0.05) ÷ 36 = **316.67 元/月**

### 关键接口

- `GET /api/ledger` — 查询台账列表
- `GET /api/ledger/asset/{assetId}` — 按资产 ID 查询台账
- `GET /api/ledger/{id}` — 查询单个台账

### 业务规则

- 资产登记审批通过后，自动创建一条台账记录
- 台账编号格式：`LEDGER-YYYYMMDD-NNNNNN`
- 金额字段使用 BigDecimal，精确到分

### 折旧任务逻辑

```

  → 查询所有非报废状态的台账记录

       accumulatedDepreciation += monthlyDepreciation
       monthsUsed += 1
       netValue = originalValue - accumulatedDepreciation

```

}

## 开发建议

1. **每个模块按 entity → mapper → service → controller 的顺序开发**
2. **先写实体类，再写 Mapper 接口，再写 Service，最后写 Controller**
3. **每完成一个模块，用 Postman 或 curl 测试接口是否正常**
4. **金额字段一律使用 BigDecimal，不要用 double**
5. **日期时间一律使用 LocalDateTime/LocalDate，不要用 Date**
6. **所有核心实体使用软删除（is_deleted 标记）**
7. **统一返回格式 Result<T>，不要直接在 Controller 里返回 Map**
8. **快照冗余是关键设计，每个单据都要保存操作时的关键信息**
